# Итоговый аналитический отчет (Лабораторная работа №1)

## 1. Резюме (Executive Summary)
В рамках лабораторной работы был спроектирован процесс разработки микросервиса «Расчет корзины и скидок». Настроена безопасная инфраструктура ведения веток (Git Flow), развернуты автоматические Quality Gates (CI/CD) на базе линтера Flake8, проведен рефакторинг структуры проекта, а также составлен регламентированный план проведения Code Review.

## 3. Архитектура и контроль версий
### 3.1. Настройка репозитория
Использована модель ветвления Git Flow (ветки `main`, `develop`, префиксы `feature/`, `ci/`, `docs/`).
* Ссылка на репозиторий: https://github.com

### 3.2. Контроль доступа
Ветка `develop` защищена правилом Branch Protection (требуется Pull Request перед слиянием). Настроен файл `CODEOWNERS`, требующий обязательного назначения ревьюера.

## 4. Инструментальный контроль качества
### 4.1. Настройка CI/CD
Настроен автоматический запуск линтера Flake8 при создании Pull Request в ветку `develop`. Конфигурация описана в файле `.github/workflows/qa.yml`.

### 4.2. Работа Quality Gate
В процессе тестирования линтер заблокировал коммит из-за ошибок синтаксиса и структуры (лишний импорт и строка > 80 символов). Файлы были очищены от мусора, а код в `src/discount.py` приведен к стандартам PEP8, после чего пайплайн успешно прошел проверку и загорелся зеленым статусом.

## 5. Обратное проектирование и планирование ревью
### 5.1. Анализ алгоритма и запахи кода (Code Smells)
В ходе анализа legacy-кода были выявлены следующие архитектурные проблемы:
1. **Магические числа (Magic Numbers):** Коэффициенты скидок и жестко зашитые вычитаемые суммы лояльности прямо в теле условий.
2. **Жесткая кодировка (Hardcoded Values):** Строковые названия промокодов (например, `"SUMMER"`, `"VIP"`) вшиты в логику обработчика.
3. **Нарушение принципа единственной ответственности:** Модуль одновременно отвечает и за расчет корзины, и за валидацию уровней лояльности, и за применение промокодов.
